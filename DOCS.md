# Beat Slicer — техническая документация

Ритм-слэшер в одном HTML-файле (`beat_slicer.html`): руби неоновые шары в такт музыке.
Без сборки и зависимостей — Canvas 2D + Web Audio API, открывается двойным кликом
(режим «звук вкладки» требует Chrome). `index-original.html` — снапшот ранней версии до
всех правок этой итерации.

Мобильная ветка использует `mobile/beat_slicer_mobile.source.html`; команда
`python3 tools/build_mobile.py` создаёт автономный `beat_slicer_mobile.html` с обоими
MP3 внутри. Подробности — в `mobile/README.md`.

---

## 1. Архитектура

Один файл, один глобальный стейт `G` (доступен как `window.G` для отладки), один rAF-цикл.
Разделы скрипта в порядке следования:

| Раздел | Что делает |
|---|---|
| аудио | `AudioContext`, `AnalyserNode` (fftSize 2048, smoothing 0 — сглаживание убивает спектральный флюкс) |
| офлайн-анализ | построение битовой сетки трека-файла до старта игры |
| реалтайм-детект | бит-трекинг звука вкладки + предсказание |
| спавн | шары, бомбы, ноты карты |
| слайс | геометрия разреза, очки, комбо, бомбы |
| ввод | pointer-события, порог скорости взмаха |
| игровой цикл | `update` (физика) + `draw` (рендер) |
| UI/режимы | меню, HUD, старт/стоп, файл, звук вкладки и ручной уровень |

### Режимы источника звука
- **Трек-файл** — самый точный: `decodeAudioData` → полный офлайн-анализ → карта нот заранее.
- **Звук вкладки** — `getDisplayMedia` c аудио (только Chrome), поток идёт в анализатор, звук играет в исходной вкладке.
- **Level: Free Flow Flava — Mistake** — отдельная ручная карта с включённым MP3;
  запускается одной кнопкой на выбранной сложности.
- **Level: QMIIR — YALA (Slowed)** — второй встроенный MP3 с собственной сеткой,
  структурой, тремя сложностями, Rush-сериями и независимыми рекордами.

## 2. Аудио-пайплайн

### 2.1 Офлайн (режим «файл»)
1. **Onset envelope** — энергия в 3 полосах (низ/середина/верх, однополюсные фильтры),
   лог-компрессия, положительная производная (spectral flux), бас с весом ×2.
   Хоп ~11.6 мс. Видит кик даже под лимитером.
2. **Темп** — автокорреляция огибающей (60–240 BPM), лог-гауссово предпочтение ~120 BPM,
   вторая гармоника против октавных ошибок, параболическое уточнение вершины.
3. **Биты** — динамическое программирование (битрекинг Ellis 2007): следует за дрейфом
   темпа сам, штраф за отклонение от целевого интервала.
4. **Карта** (`buildMap`) — громкость секции ±1.5 с в дБ → 4 уровня активности с
   гистерезисом, плотность меняется только на границе такта. Тишина (−30 дБ от пика) — пауза.

### 2.2 Реалтайм (звук вкладки)
Схема BTrack, упрощённая, плюс «слух наперёд»:
- **Adaptive whitening** — каждый бин спектра нормируется на свой бегущий максимум
  (спад ~1 с): детект не зависит от громкости источника.
- **Флюкс + адаптивный порог** — онсеты; медиана интервалов даёт грубый темп.
- **Глобальный BPM** — огибающая онсетов копится в бинах по 12 мс (~12.3 с истории),
  каждые 2 с автокорреляция даёт стабильную оценку темпа; сплавляется с онсет-медианой
  (вес автокорреляции до 75% по её уверенности). Работает даже в меню — к старту игры
  темп уже «наслушан».
- **PLL-метроном** — тикает по предсказанной сетке пока музыка играет; детекты мягко
  правят фазу (±35% интервала — коррекция 0.3), 4 промаха подряд — хард-ресинк.
  Спавн с опережением 120 мс: полёт стартует по сетке, а не «когда кадр успел».
- **Фаза такта** — каждый бит голосует (бас + энергия) за свою долю mod 4; максимум —
  «раз» такта. Дабл-биты и бомбы выравниваются по нему.
- **Директор** (`updateLiveDirector`) — на границе такта: средняя энергия/бас/онсеты →
  детект дропа; интервалы между дропами дают период цикла; на прогнозном такте уровень 3
  включается **до** подтверждения энергией. Прогноз промахнулся дважды — период забывается.
- **Калибровка задержки** — медиана подписанных ошибок игрока сдвигает `liveOffset`
  (кламп −0.22…+0.12 с), сохраняется в `localStorage`.
- Тишина ~2 с — сетка гаснет, перелок на первом онсете.

## 3. Геймплей

### Ручной уровень «Mistake»
- Трек: Free Flow Flava — Mistake, 165.09 с.
- Сетка: 110.022 BPM, интервал 0.54535 с, первый downbeat 0.0145 с.
- Hard: полная карта из 298 событий, 8 бомб, 15 обычных даблов и 3 Rush-серий;
  минимальный интервал обычной карты — 1/2 бита.
- Medium и Light строятся детерминированными ритмическими масками на 3 и 2 опорных
  удара за такт. Все 40 главных атак и характерные синкопы защищены от прореживания;
  бомб и двойных целей на младших сложностях меньше.
- Итоговая плотность: Light — 162 события (58.9/мин, 2 бомбы, без обычных даблов),
  Medium — 210 (76.3/мин, 4 бомбы, 7 обычных даблов), Hard — 298 (108.3/мин,
  8 бомб, 15 обычных даблов). Средняя плотность активного такта: 2.35 / 3.21 / 4.85.
- Структура вручную размечена по 76 тактам: интро, куплет, билдап, два дропа,
  бридж и финальный аккорд.
- Все 40 сильнейших онсет-пиков офлайн-анализа имеют цель не дальше 140 мс.
- MP3 хранится рядом с HTML как ресурс уровня и подхватывается автоматически.
- В ручном уровне `<audio>` играет напрямую, без `MediaElementAudioSource`: это избегает
  немого вывода Chrome для локального `file://`, а синхронизация берётся из `currentTime`.
  Для эквалайзера отдельная копия сигнала идёт через `captureStream()` только в
  `AnalyserNode`; если API недоступен, включается детерминированная визуальная модель карты.

### Ручной уровень «YALA (Slowed)»
- Трек: QMIIR / DJ Zarek / Irokz — YALA (Slowed), 159.0335 с.
- Сетка: 84.0863 BPM, интервал 0.7135526 с, `bar0` 0.0254 с, 56 тактов.
- Структура: интро 0–3, дроп A 4–11, брейк/техническая фраза 12–20,
  дроп B 21–28, бридж 29–36, финальный дроп 37–52, fade 53–54, тишина 55.
- Light: 135 событий, 141 цель, 2 бомбы, без обычных даблов.
- Medium: 165 событий, 173 цели, 4 бомбы, 4 обычных дабла.
- Hard: 234 события, 242 цели, 7 бомб, 7 обычных даблов.
- Все 40 сильнейших onset-пиков имеют игровую цель не дальше 140 мс на каждой сложности.
- Три Samurai Rush стоят на тактах 4 / 21 / 37 (3 / 4 / 4 цели): вход первого
  дропа, второго дропа и главная атака финальной части.
- Начало тишины привязано к `bar 55, q0.5` (157.3637483 с). Две секунды заканчиваются
  в 159.3637483 с — на 0.33 с после физического MP3; поэтому финиш использует часы
  `AudioContext`, которые продолжают идти после `audio.onended`.

### Samurai Rush
- Три редкие сюжетные серии стоят на тактах 16, 40 и 68: вход в первый дроп,
  главный пик трека и финальная кульминация.
- Серии содержат 3 / 4 / 4 цели на шестнадцатых. Они летят короткой неровной
  диагональю, поэтому требуют последовательного взмаха, а не одного прямого среза.
- Полностью закрытая в ритмическом окне серия даёт +750; если все цели попали в PERFECT — +1500.
  Дополнительных звуков поверх трека механика не создаёт.

### Финальный SCORE и звёзды
- Последняя цель не обрывает аудио. Fade проверен по mono PCM блоками по 100 мс;
  последняя точка выше −60 dB заканчивается до 160.3 с. Начало подтверждённой тишины
  привязано к `bar 73, q2` (160.3474 с), результат появляется после ещё двух полных
  секунд — в 162.3474 с. Физический пустой хвост MP3 после этого не проигрывается.
- Игровой кадр затемняется отдельным fullscreen-overlay: `SCORE` крупно досчитывается
  от нуля, затем три неоновые звезды последовательно заполняются. Незаработанные
  звёзды остаются золотым контуром.
- Теоретический максимум считается из реального числа целей карты: все PERFECT,
  непрерывное комбо, максимальные Rush-бонусы, бомбы не задеты.
- Light физически проще и требует более высокий процент максимума; Hard допускает
  меньший процент, но его абсолютные пороги всё равно значительно выше.
- Каждое завершение сохраняется в `localStorage` по ключу
  `beat-slicer:result:v1:<track-id>:<difficulty>`. Track ID: `free-flow-flava--mistake`
  или `qmiir--yala-slowed`. Внутри лежат `latest` и `best`; треки и сложности не
  перезаписывают результаты друг друга.
- В меню под каждой кнопкой уровня отдельная карточка сразу показывает лучший `SCORE`
  и контур/заполнение трёх звёзд; Light/Medium/Hard обновляет обе карточки.

### Сложности

### Плотность спавна (единая для звука вкладки и файла)
- Light: базовый шар через бит; офбиты только на дропе раз в такт.
- Medium: каждый бит на активных участках (уровень 2+), иначе через бит; офбиты — дроп, раз в такт.
- Hard: каждый бит; офбиты — дроп через один, разгон раз в такт.

### Очки и множитель
- Разрез: PERFECT ±90–140 мс (live уже после калибровки) = 300, дальше 200/100. Всё ×множитель.
- Ранний разрез (до появления кольца-подсказки) = −150 и сброс комбо. Промах = −100.
- **Множитель** `multOf(combo)`: ×2 с 4 подряд (быстрый вход в драйв), ×3 с 12, ×4 с 24,
  ×5 с 40, дальше каждые +24. Единая функция — очки, HUD, неон и фон считают одинаково.
- **Бомба** = −400, сброс комбо, и взрыв **выжигает все шары на экране** (каждый −50,
  уходит взрывом, не разрезом). Соседние бомбы детонируют визуально без доп. штрафа.
- Бомбы — вероятность за спавн (×1.5 на дропе, ×0.5 на спокойном), минимум 1.2 с между ними.
- Остановил мышь на 2.6 с — пассивный режим без штрафов; движение возвращает с 4-битной
  «слушаем такт» отсрочкой.

## 4. Визуал

Всё на Canvas 2D, один проход, без WebGL.

- **Шары** — неоновые «шайбы» в стиле glow hockey: тёмная сердцевина, толстое цветное
  кольцо с shadowBlur, белая раскалённая кромка, аддитивное гало.
- **Разруб** — половинки как во Fruit Ninja: две неоновые полуокружности разлетаются
  перпендикулярно линии взмаха, наследуют 35% скорости шара, крутятся, гаснут за 0.8 с.
  Плюс «росчерк» — белая полоса с цветным ореолом вдоль линии реза (0.16 с).
- **След** — техника оригинального Fruit Ninja: прореживание точек по радиальной
  дистанции (5px) → сглаживание Чайкина (2 прохода) → единый ленточный полигон по
  нормалям. Профиль клинка: `sin^0.65` — широко в середине, острия с обоих концов.
  Три слоя: гало → цветное тело с градиентом → белое лезвие. Скорость взмаха (EMA)
  раздувает ширину, комбо усиливает свечение и сдвигает цвет.
- **Искры** — не кружки, а штрихи вдоль вектора полёта (длина от скорости, до 26px),
  белая сердцевина, мерцание альфы — «резка металла». Летят только в момент разруба.
- **Взрыв бомбы** — намеренно «выбивающийся» из неона: белый флешбенг на ~2 кадра,
  красное послесвечение, рваный зазубренный фронт (26 вершин с джиттером, грязный
  оранжево-красный, обычный composite), тёмные клубы копоти, тряска 44.
- **Множитель** — центральный элемент: неоновый `×N` вверху по центру, пульсирует под
  каждый бит (`exp(-5·Δt)` от таймстампа бита), растёт/меняет оттенок с N, вспышка и
  `MULTIPLIER ×N` на повышении, краснеет на сбросе, тлеет на ×1.
- **Фон — «подогрев драйва»**: радиальное свечение и эквалайзер гейтятся множителем:
  ×1 — фон погашен, бары еле тлеют; ×2 — мерцает под бит; ×3+ — ярче; сброс комбо
  плавно гасит всё («выключили свет»). В меню гейта нет.
- **Эквалайзер** — классический столбчатый (56 квадратных баров, fillRect, зазор 2px),
  сглаживание: атака 0.3, спад 0.94.

## 5. От чего отказались (и почему)

| Идея | Причина отказа |
|---|---|
| Залитые градиентные шары | «Клоунские носы» — заменены неоновыми кольцами |
| Посегментный след (stroke с round cap) | Каждый сегмент давал «бусину» — заменён лентой Чайкина |
| Большая голова следа | Комета вместо лезвия — профиль стал `sin`, острия с двух концов |
| Искры с лезвия при быстрых взмахах | Визуальный мусор — искры остались только в момент разруба |
| Неоновые кольца при взрыве бомбы | Слишком «красиво» — взрыв должен ощущаться неприятно; рваный фронт + флешбенг + копоть |
| Плавающий текст `COMBO ×N` | Дублировал неоновый множитель |
| Бомба по фикс. слоту `step%32===28` | Слишком редко и предсказуемо — вероятность за спавн |
| Множитель `1+floor(combo/10)` | Слишком долгий выход на ×2 — ступени 4/12/24/40 |
| Волновой эквалайзер внизу | Смотрелся хуже баров |
| Волна сверху под каунтером | Выглядела как интерактивный элемент |
| Волны по бокам («танцпол») | «Херня» © |
| Бары-«пилюли» с точкой-вершинкой | Точки читались как отдельные объекты, зазоры «как зубы» |
| Широкие бары внахлёст | Возврат к дефолтным квадратным — они выигрывали |
| Фикс. вес офбитов на Normal/Hard | После усиления директора сыпало нечитаемо много шаров |

## 6. Отладка

- `window.G` — весь стейт (в т.ч. `G.rt` — реалтайм-трекер, `G.director` — директор дропов).
- `window.__bs.a` — доступ к `analyzeTrack`, `buildMap`, `DIFF` из консоли.
- После анализа файла в консоль пишется: BPM, число битов, ритмичность, нот/мин.
- Проверка синтаксиса: `node --check` на извлечённом `<script>` (тайпчекер/линтер не настроены).

## 7. Известные компромиссы

- Смена сильной доли (`phaseShift`) сдвигает чётность шагов — плотность офбитов может
  «мигнуть» на один такт при переучивании.
- Live-темп фолдится в 80–160 BPM: на очень медленных/быстрых треках играется
  половина/удвоение темпа.
- Бомба заменяет шар, а не добавляется к нему.
- Хитбокс шара (`r+8`) шире визуального неонового кольца — осознанно, прощает.

## 8. Как добавить заранее размеченный трек

### 8.1 Готовый анализатор

В репозитории есть [`tools/analyze_track.py`](tools/analyze_track.py). Требования:
Python 3, NumPy, `ffmpeg` и `ffprobe`. Скрипт сам декодирует MP3 в mono PCM и считает:

- onset-flux по общей, басовой и верхней полосам;
- BPM автокорреляцией и уточнением по сильным пикам;
- фазу half-beat-сетки и сильную долю 4/4;
- громкость, бас, onset и peak по каждому такту;
- сильнейшие атаки, предполагаемые секции и редкие кандидаты для специальных атак.

Полная команда для нового трека:

```bash
python3 tools/analyze_track.py "/absolute/path/New Track.mp3" \
  --out "/tmp/new-track.analysis.json" \
  --emit-js "/tmp/new-track.level.js"
```

Для нестандартного темпа можно ограничить поиск:

```bash
python3 tools/analyze_track.py track.mp3 --bpm-min 75 --bpm-max 150 \
  --peaks 100 --out /tmp/track.json
```

Скрипт не генерирует финальную карту случайно. Он создаёт измерения, по которым агент
осмысленно размечает музыкальный сюжет. `--emit-js` выдаёт готовые `TRACK_ANALYSIS` и
функцию `T(bar,q)` для вставки в код.

### 8.2 Контракт JSON

Главные поля:

```text
track.duration          длительность оригинального файла
grid.bpm                уточнённый BPM
grid.interval           длительность одной четверти в секундах
grid.bar0               время сильной доли первого такта
grid.confidence         отношение лучшей автокорреляции к медианной
bars[]                  профиль каждого такта
topPeaks[]              атаки, отсортированные по силе
sections[]              черновое деление на silence/low/active/drop
attackCandidates[]      кандидаты для Samurai Rush и других кульминаций
```

Перевод времени пика в координаты карты:

```js
const beat = (peak.t - analysis.grid.bar0) / analysis.grid.interval;
const bar = Math.floor(beat / 4);
const q = beat - bar * 4;
const snappedQ = Math.round(q * 4) / 4; // сетка шестнадцатых
const eventTime = analysis.grid.bar0 + (bar * 4 + snappedQ) * analysis.grid.interval;
```

В `q` одна целая единица — четверть, `.5` — восьмая, `.25` — шестнадцатая.

### 8.3 Разметка карты

1. Скопировать MP3 рядом с `beat_slicer.html`; не перекодировать после анализа.
2. Запустить анализатор и проверить в stdout BPM, число тактов и `bar0`.
3. Просмотреть `bars`, `sections` и `topPeaks`; секции скрипта — подсказка, а не истина.
4. Создать константу уровня и `T(bar,q)`. Сначала расставить downbeat и 30–40
   сильнейших `topPeaks`, затем заполнить музыкальные фразы, филлы и бомбы.
5. Специальные серии ставить только в нескольких сюжетных кульминациях. Проверить их
   на слух; высокий `attackCandidates.score` сам по себе ещё не доказывает дроп.
6. Hard хранит полную авторскую карту. Medium и Light строятся детерминированными
   масками по сетке; все главные пики должны быть защищены отдельным `Set` якорей.
7. Не менять скорость полёта внутри трека. Сложность меняется плотностью, радиусом,
   порогом взмаха, количеством бомб/даблов и редкими специальными паттернами.

Минимальный каркас карты:

```js
const LEVEL={title:'Artist — Track',dur:165.09,iv:.54545,off:.0033};
function buildChart(diff='hard'){
  const T=(bar,q)=>LEVEL.off+(bar*4+q)*LEVEL.iv;
  const notes=[];
  const orb=(bar,q,side)=>notes.push({t:T(bar,q),bar,q,side,orbs:1,bomb:false});
  const dbl=(bar,q)=>notes.push({t:T(bar,q),bar,q,orbs:2,bomb:false});
  const bomb=(bar,q)=>notes.push({t:T(bar,q),bar,q,orbs:0,bomb:true});
  // Ручная разметка секций и акцентов здесь.
  notes.sort((a,b)=>a.t-b.t);
  return {notes,light:[]};
}
```

### 8.4 Подключение встроенного аудио

Локальный MP3 нельзя пропускать через `createMediaElementSource`: Chrome под `file://`
может вывести тишину. Правильная схема:

```html
<audio id="levelAudio" src="Track.mp3" preload="auto" hidden></audio>
```

```js
levelAudio.muted=false;
levelAudio.volume=1;
await levelAudio.play();                 // прямой слышимый выход
G.songStart=AC.currentTime-levelAudio.currentTime;

const stream=levelAudio.captureStream?.();
if(stream?.getAudioTracks().length){
  const visualSource=AC.createMediaStreamSource(stream);
  visualSource.connect(analyser);         // только эквалайзер, не destination
}
```

`captureStream()` нельзя подключать к `AC.destination`: звук уже играет напрямую,
иначе получится дубль. Для неподдерживаемых браузеров нужен визуальный fallback.
